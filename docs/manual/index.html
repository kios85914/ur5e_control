UR5e · pure control libraryUR5e · 純制御ライブラリUR5e · 純控制函式庫

Drive the arm.アームを動かす。驅動機械臂。_

A clean, dependency-free Python library for commanding a Universal Robots UR5e over the URScript socket transport — full 6-DOF Cartesian and joint motion, with a forward-looking Robotiq FT 300 force-control subsystem.

URScript ソケット経由で Universal Robots UR5e を制御する、依存ゼロのクリーンな Python ライブラリ。6 自由度のデカルト空間・関節空間モーションに対応し、将来の Robotiq FT 300 力制御サブシステムを見据えた設計です。

透過 URScript socket 控制 Universal Robots UR5e 的乾淨、零依賴 Python 函式庫 — 完整 6 自由度的笛卡兒空間與關節空間運動,並預留 Robotiq FT 300 力量控制子系統。

Quick Startクイックスタート快速開始

Connect, move the tool to a Cartesian pose, read state, return home.

接続し、ツールをデカルト姿勢へ動かし、状態を読み取り、ホームへ戻します。

連接、把工具移動到笛卡兒姿態、讀取狀態、回到 home。

first_move.py
from ur5e_control import UR5eRobot, RobotConfig

with UR5eRobot(RobotConfig()) as robot:          # connects on enter, disconnects on exit
    if not robot.wait_until_connected():            # wait for the daemon to dial back
        raise SystemExit("robot did not connect")
    print("robot connected")

    robot.move_l([0.0, -0.35, 0.25, 0.0, -3.14, 0.0])  # world frame, m / rad

    state = robot.get_state()                       # RobotState (UR base frame)
    print(state.tcp_pose, state.wrench)

    robot.move_l([0.0, 0.0, 0.05, 0, 0, 0], relative=True)  # 5 cm up, relative
    robot.home()                                  # move to config.home_pose
What connect() does: uploads the URScript daemon to the controller (controller_ip:script_port), then opens the PC-side socket so the daemon's state stream starts flowing back. Everything else is delegated to the motion layer.connect() の動作: URScript デーモンをコントローラ（controller_ip:script_port）にアップロードし、PC 側のソケットを開いてデーモンからの状態ストリームを受信し始めます。それ以外はすべてモーション層に委譲されます。connect() 做的事: 把 URScript daemon 上傳到控制器（controller_ip:script_port）,然後開啟 PC 端 socket 讓 daemon 的狀態串流回傳。其餘都委派給 motion 層。

Architectureアーキテクチャ架構

Startup brings the daemon up; then the PC and controller exchange information in a loop — like an RL agent↔environment cycle, with the command as the action and the state as the observation.

起動でデーモンを立ち上げ、その後 PC とコントローラがループで情報をやり取りします — RL のエージェント↔環境サイクルのように、コマンドが行動、状態が観測に相当します。

啟動會把 daemon 拉起;之後 PC 與控制器以迴圈交換資訊 — 就像 RL 的 agent↔環境 循環,command 是 action、state 是 observation。

startup / bring-up起動・立ち上げ啟動 / 拉起 command (PC → controller)コマンド（PC → コントローラ）command（PC → 控制器） state (controller → PC)状態（コントローラ → PC）state（控制器 → PC）

How data flows through the code (call order)コード内のデータの流れ（呼び出し順）資料如何在程式碼間流動(呼叫順序)

Same nodes, zoomed in: a command you call is encoded layer by layer on the way down to the robot; the robot's state is parsed layer by layer on the way up into a RobotState. The label on each step is the data handed to the next node.

同じノードの拡大図: あなたが呼ぶコマンドは下りで層ごとにエンコードされ機器人へ、機器人の状態は上りで層ごとにパースされ RobotState になります。各ステップのラベルが次のノードへ渡すデータです。

同樣的節點放大看:你呼叫的指令在下行時一層層被編碼送到機器人;機器人的狀態在上行時一層層被解析成 RobotState。每一步的標籤就是傳給下一個節點的資料。

Protocol & Framesプロトコルと座標系協定與座標系

Everything is meters, radians, and the UR base frame. World↔UR conversion is explicit in RobotConfig — there is no hidden negation.

すべてメートル・ラジアン・UR ベース座標系です。World↔UR 変換は RobotConfig に明示されており、隠れた符号反転はありません。

全部都是公尺、弧度、UR 基座座標系。World↔UR 轉換在 RobotConfig 中明確定義 — 沒有隱藏的符號反轉。

UR5eRobot — the facade— ファサード— 門面

UR5eRobot(config: RobotConfig = RobotConfig())
Construct the robot. No I/O happens until connect(). Usable as a context manager.ロボットを構築。connect() まで I/O は発生しません。コンテキストマネージャとして使用可能。建立機器人。connect() 之前不會有 I/O。可作為 context manager 使用。
connect() → None  ·  disconnect() → None
connect() uploads the daemon then starts the state connection. disconnect() closes it (idempotent). Both are driven automatically by the with block.connect() はデーモンをアップロードしてから状態接続を開始。disconnect() はそれを閉じます（冪等）。どちらも with ブロックが自動実行します。connect() 上傳 daemon 然後啟動狀態連線。disconnect() 關閉它（冪等）。兩者都由 with 區塊自動執行。
wait_until_connected(timeout=5.0, poll=0.1) → bool
connect() returns once the PC is listening; the daemon dials back a moment later. This blocks until that callback (is_daemon_connected() true) and returns True, or False on timeout. In dry-run it returns False immediately (check robot.dry_run). Use it to confirm the robot is really up before commanding.connect() は PC が待ち受け開始した時点で返り、デーモンは少し後に接続し返します。これはそのコールバック（is_daemon_connected() が真）まで待って True、タイムアウトで False を返します。dry-run では即 False（robot.dry_run で判別）。コマンド前の接続確認に使います。connect() 在 PC 開始監聽時就回傳;daemon 稍後才回連。這個方法會等到那個回連(is_daemon_connected() 為真)回傳 True,逾時則 False。dry-run 會立刻回 False(用 robot.dry_run 區分)。下指令前用它確認機器人真的上線。
move_l(pose, speed=None, accel=None, blocking=True, relative=False) → None
Linear (Cartesian) move of the TCP. pose is a world-frame [x, y, z, rx, ry, rz] in m/rad (a delta if relative=True). Converted to UR frame, workspace-checked, encoded, sent; if blocking, polls until within convergence_tol.TCP の直線（デカルト）移動。pose は World 座標系の [x, y, z, rx, ry, rz]（m/rad、relative=True なら差分）。UR 座標系へ変換し、作業範囲チェック・エンコード・送信。blocking なら convergence_tol 以内に入るまでポーリング。TCP 的直線（笛卡兒）移動。pose 是 world 座標系的 [x, y, z, rx, ry, rz]（m/rad,relative=True 則為差量）。轉成 UR 座標系、檢查工作範圍、編碼、送出;若 blocking,輪詢到誤差 < convergence_tol。 raises WorkspaceViolation · SpeedViolation
move_j(joints, speed=None, accel=None, blocking=True) → None
Joint-space move. joints = [j0..j5] in radians (frame-independent). Joint-limit checked; if blocking, waits for the TCP pose to settle.関節空間の移動。joints = [j0..j5]（ラジアン、座標系に非依存）。関節制限をチェックし、blocking なら TCP 姿勢が落ち着くまで待機。關節空間移動。joints = [j0..j5]（弧度,與座標系無關）。檢查關節上限;若 blocking,等待 TCP 姿態穩定。 raises JointLimitViolation · SpeedViolation
get_state() → RobotState
Parse the latest streamed frame into a RobotState (UR base frame).最新の状態フレームを RobotState（UR ベース座標系）にパース。把最新的狀態 frame 解析成 RobotState（UR 基座座標系）。 raises ValueError
stop() → None  ·  home() → None
stop() commands an immediate controlled stop (cmd 2, non-blocking). home() moves to config.home_pose (cmd 3).stop() は即時の制御停止（cmd 2、非ブロッキング）。home() は config.home_pose へ移動（cmd 3）。stop() 下達立即受控停止（cmd 2,非阻塞）。home() 移動到 config.home_pose（cmd 3）。

Methods world_to_ur(pose) / ur_to_world(pose) convert between frames. Default is identity (world == UR base frame). Override them in RobotConfig if your world frame differs (e.g. negate x/y, add an offset); keep them mutual inverses.

world_to_ur(pose) / ur_to_world(pose) 在座標系間轉換。預設為 identity(world == UR 基座座標系)。若你的 world 座標不同,在 RobotConfig 覆寫(例如反轉 x/y 或加偏移);兩者要互為反運算。

Why two backends. A guarded move is a force threshold, so the PC velocity loop is fine and latency-tolerant. Regulating a force / rendering impedance against stiff contact is a high-bandwidth feedback loop — a PC loop at tens of Hz would chatter, so behaviors ② and ③ run on the controller's 500 Hz force_mode. They stay gated (FORCE_MODE_ENABLED=False) pending on-robot validation; enabling a wrong force_mode is a real safety hazard. The daemon also exits force_mode cooperatively (never hard-killed mid-compliance).2 バックエンドの理由。ガード付き移動は力のしきい値判定なので PC 速度ループで十分（遅延に強い）。剛な接触で力を調節/インピーダンスを実現するのは高帯域フィードバックで、数十 Hz の PC ループでは振動するため、②③ はコントローラの 500 Hz force_mode で実行。FORCE_MODE_ENABLED=False でロックし実機検証待ち（誤った force_mode は安全上の危険）。デーモンは force_mode を協調的に終了します（順応中の強制 kill はしない）。為何兩個後端。guarded move 是力閾值判定,PC 速度迴圈就夠且耐延遲。對剛性接觸做力調節/impedance 是高頻寬回授,數十 Hz 的 PC 迴圈會抖動,所以 ②③ 跑在控制器的 500 Hz force_mode。以 FORCE_MODE_ENABLED=False 鎖住、待上機驗證(錯誤的 force_mode 有實際安全風險)。daemon 也以合作式退出 force_mode(順應中絕不硬 kill)。
