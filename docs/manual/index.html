UR5e · pure control libraryUR5e · 純制御ライブラリ

Drive the arm.アームを動かす。_

A clean, dependency-free Python library for commanding a Universal Robots UR5e over the URScript socket transport — full 6-DOF Cartesian and joint motion, with a forward-looking Robotiq FT 300 force-control subsystem.

URScript ソケット経由で Universal Robots UR5e を制御する、依存ゼロのクリーンな Python ライブラリ。6 自由度のデカルト空間・関節空間モーションに対応し、将来の Robotiq FT 300 力制御サブシステムを見据えた設計です。

This library moves a real robot arm. Read the Safety section before connecting to hardware. The library itself is verified only by code-level tests (parsing, encoding, safety, control law via mocks) — on-robot validation is the operator's responsibility.このライブラリは実機のロボットアームを動かします。ハードウェアに接続する前に必ず「安全」セクションを読んでください。ライブラリ自体はコードレベルのテスト（パース・エンコード・安全検証・モックによる制御則）でのみ検証されています。実機での検証は操作者の責任です。

Quick Startクイックスタート

Connect, move the tool to a Cartesian pose, read state, return home.

接続し、ツールをデカルト姿勢へ動かし、状態を読み取り、ホームへ戻します。

first_move.py
from ur5e_control import UR5eRobot, RobotConfig

with UR5eRobot(RobotConfig()) as robot:          # connects on enter, disconnects on exit
    robot.move_l([0.1, 0.3, 0.2, 0.0, -3.14, 0.0])  # world frame, m / rad

    state = robot.get_state()                       # RobotState (UR base frame)
    print(state.tcp_pose, state.wrench)

    robot.move_l([0.0, 0.0, 0.05, 0, 0, 0], relative=True)  # 5 cm up, relative
    robot.home()                                  # move to config.home_pose
What connect() does: uploads the URScript daemon to the controller (controller_ip:script_port), then opens the PC-side socket so the daemon's state stream starts flowing back. Everything else is delegated to the motion layer.connect() の動作: URScript デーモンをコントローラ（controller_ip:script_port）にアップロードし、PC 側のソケットを開いてデーモンからの状態ストリームを受信し始めます。それ以外はすべてモーション層に委譲されます。

Architectureアーキテクチャ

Startup brings the daemon up; then the PC and controller exchange information in a loop — like an RL agent↔environment cycle, with the command as the action and the state as the observation.

起動でデーモンを立ち上げ、その後 PC とコントローラがループで情報をやり取りします — RL のエージェント↔環境サイクルのように、コマンドが行動、状態が観測に相当します。

Protocol & Framesプロトコルと座標系

Everything is meters, radians, and the UR base frame. World↔UR conversion is explicit in RobotConfig — there is no hidden negation.

すべてメートル・ラジアン・UR ベース座標系です。World↔UR 変換は RobotConfig に明示されており、隠れた符号反転はありません。

固定 10 個の float の ASCII 文字列: "(cmd, a0, a1, a2, a3, a4, a5, accel, vel, time)"。デーモンは socket_read_ascii_float(10, …) で読み取ります。

The public surface. Per-module markdown lives in docs/api/.

UR5eRobot — the facade— ファサード

UR5eRobot(config: RobotConfig = RobotConfig())
Construct the robot. No I/O happens until connect(). Usable as a context manager.ロボットを構築。connect() まで I/O は発生しません。コンテキストマネージャとして使用可能。
connect() → None  ·  disconnect() → None
connect() uploads the daemon then starts the state connection. disconnect() closes it (idempotent). Both are driven automatically by the with block.connect() はデーモンをアップロードしてから状態接続を開始。disconnect() はそれを閉じます（冪等）。どちらも with ブロックが自動実行します。
move_l(pose, speed=None, accel=None, blocking=True, relative=False) → None
Linear (Cartesian) move of the TCP. pose is a world-frame [x, y, z, rx, ry, rz] in m/rad (a delta if relative=True). Converted to UR frame, workspace-checked, encoded, sent; if blocking, polls until within convergence_tol.TCP の直線（デカルト）移動。pose は World 座標系の [x, y, z, rx, ry, rz]（m/rad、relative=True なら差分）。UR 座標系へ変換し、作業範囲チェック・エンコード・送信。blocking なら convergence_tol 以内に入るまでポーリング。 raises WorkspaceViolation · SpeedViolation
move_j(joints, speed=None, accel=None, blocking=True) → None
Joint-space move. joints = [j0..j5] in radians (frame-independent). Joint-limit checked; if blocking, waits for the TCP pose to settle.関節空間の移動。joints = [j0..j5]（ラジアン、座標系に非依存）。関節制限をチェックし、blocking なら TCP 姿勢が落ち着くまで待機。 raises JointLimitViolation · SpeedViolation
get_state() → RobotState
Parse the latest streamed frame into a RobotState (UR base frame).最新の状態フレームを RobotState（UR ベース座標系）にパース。 raises ValueError
stop() → None  ·  home() → None
stop() commands an immediate controlled stop (cmd 2, non-blocking). home() moves to config.home_pose (cmd 3).stop() は即時の制御停止（cmd 2、非ブロッキング）。home() は config.home_pose へ移動（cmd 3）。

Safety安全

This commands a physical robot. Treat every move as live.これは実機のロボットを操作します。すべての動作を本番として扱ってください。

  • Keep the e-stop within reach. The physical emergency stop on the teach pendant is your real safety device — not robot.stop().非常停止を手の届く所に。本当の安全装置はティーチペンダントの物理非常停止であり、robot.stop() ではありません。
  • Clear the workspace of people and obstacles before connect(). The first command may move the arm immediately.作業領域を片付ける。connect() の前に人と障害物を除去してください。最初のコマンドで即座にアームが動く可能性があります。
  • Start slow. Verify motions at low speed first. Keep max_speed conservative; it is a hard cap, not a suggestion.低速から。まず低い speed で動作を確認。max_speed は控えめに — これは提案ではなくハード上限です。
  • Validate workspace_limits for your cell. Defaults come from a different setup. A pose outside bounds raises WorkspaceViolation and is never sent — set them correctly.あなたのセルに合わせて workspace_limits を検証。デフォルトは別環境のものです。範囲外の姿勢は WorkspaceViolation を送出し送信されません — 正しく設定してください。
  • Force control is disabled by default. The daemon's cmd 4 branch is gated behind FORCE_MODE_ENABLED = False so a stray force command cannot drive the arm into a surface before the FT 300 is validated.力制御はデフォルトで無効。デーモンの cmd 4 分岐は FORCE_MODE_ENABLED = False でガードされ、FT 300 の検証前に誤った力コマンドでアームを面に押し付けることはありません。
  • Dry-run first. Use the dry-run transport / examples to inspect the exact command strings before any of them reach the controller.まず dry-run。dry-run トランスポート/サンプルで、コントローラに届く前に正確なコマンド文字列を確認してください。
Verification scope. This library is tested only at the code level (parsing, command encoding, safety validation, control law via mocks). Motion correctness on real hardware has not been verified and must be confirmed by the operator on the actual UR5e + cell.検証範囲。このライブラリはコードレベル（パース・コマンドエンコード・安全検証・モックによる制御則）でのみテストされています。実機での動作の正しさは検証されておらず、実際の UR5e とセルで操作者が確認する必要があります。

Force Control力制御 Robotiq FT 300 · forward-looking将来対応

Move along a direction until contact force reaches a target, then hold compliantly (impedance). Interfaces and the control law are implemented and mock-tested; on-robot tuning happens once the FT 300 is mounted.

ある方向へ接触力が目標に達するまで移動し、その後コンプライアントに（インピーダンス）保持します。インタフェースと制御則は実装・モックテスト済み。実機調整は FT 300 装着後に行います。

Pending hardware validation. Step size, stiffness, threshold and max_travel are placeholders to tune on the real sensor. The daemon's force branch stays disabled until you set FORCE_MODE_ENABLED = True in motion_daemon.script after validation.ハードウェア検証待ち。ステップ幅・剛性・しきい値・max_travel は実センサで調整するプレースホルダです。デーモンの力分岐は、検証後に motion_daemon.script で FORCE_MODE_ENABLED = True に設定するまで無効のままです。

approach-until-force, then hold力に達するまで接近して保持

force demo (mock)
from ur5e_control.force.sensor import MockForceSensor
from ur5e_control.force.controller import ForceController

# wrenches climb toward contact; last one trips the 5 N target on +Z
sensor = MockForceSensor([[0,0,1,0,0,0], [0,0,3,0,0,0], [0,0,5.2,0,0,0]])
fc = ForceController(motion, sensor, config)

fc.approach_until_force(
    direction=[0, 0, 1],   # push along +Z
    target_n=5.0,           # until |F·d| >= 5 N
    stiffness=0.08,         # compliance once in contact
    max_travel=0.12,        # safety budget (m) before giving up
)

The law reads before each step (no overshoot): below-target reads issue one relative step along the unit direction; the contact read stops stepping and emits the cmd 4 hold. Contact is decided on the force projected onto the direction, so side forces never false-trigger. Exceeding max_travel raises RuntimeError and emits no hold.

制御則は各ステップの前に読み取ります（オーバーシュート無し）: 目標未満の読み取りでは単位方向に 1 ステップだけ相対移動し、接触の読み取りでステップを止めて cmd 4 の保持を送出します。接触は方向へ射影した力で判定するため、横方向の力で誤作動しません。max_travel を超えると RuntimeError を送出し保持は出しません。
