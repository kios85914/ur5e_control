UR5e · pure control library

Drive the arm._

A clean, dependency-free Python library for commanding a Universal Robots UR5e over the URScript socket transport — full 6-DOF Cartesian and joint motion, with a forward-looking Robotiq FT 300 force-control subsystem.

0 runtime deps 129 tests passing Python 3.10+ meters · radians · base frame
This library moves a real robot arm. Read the Safety section before connecting to hardware. The library itself is verified only by code-level tests (parsing, encoding, safety, control law via mocks) — on-robot validation is the operator's responsibility.

Quick Start

Connect, move the tool to a Cartesian pose, read state, return home.

first_move.py
from ur5e_control import UR5eRobot, RobotConfig

# RobotConfig() carries IPs, ports, speed/accel defaults,
# workspace limits and the world<->UR frame transform.
with UR5eRobot(RobotConfig()) as robot:          # connects on enter, disconnects on exit
    robot.move_l([0.1, 0.3, 0.2, 0.0, -3.14, 0.0])  # world frame, m / rad

    state = robot.get_state()                       # RobotState (UR base frame)
    print(state.tcp_pose, state.wrench)

    robot.move_l([0.0, 0.0, 0.05, 0, 0, 0], relative=True)  # 5 cm up, relative
    robot.home()                                  # move to config.home_pose
What connect() does: uploads the URScript daemon to the controller (controller_ip:script_port), then opens the PC-side socket so the daemon's state stream starts flowing back. Everything else is delegated to the motion layer.

Protocol & Frames

Everything is meters, radians, and the UR base frame. World↔UR conversion is explicit in RobotConfig — there is no hidden negation.

Command tuple  (PC → daemon)

A fixed 10-float ASCII string: "(cmd, a0, a1, a2, a3, a4, a5, accel, vel, time)". The daemon reads it with socket_read_ascii_float(10, …).

cmdactiona0 … a5accel / vel / time
0moveLpose x,y,z,rx,ry,rz (m, rad)m/s², m/s, s
1moveJjoints j0..j5 (rad)rad/s², rad/s, s
2stopa0 = deceleration; rest 00
3homeall 0 → daemon uses home_posem/s², m/s, s
4force guardeda0..a2 direction · a3 target N · a4 stiffness · a5 max travelm/s², m/s, s

State frame  (daemon → PC)

Groups separated by _, each frame terminated by +. parse_state takes the last complete frame:

p[x,y,z,rx,ry,rz]_p[vx,vy,vz,wx,wy,wz]_[j0,j1,j2,j3,j4,j5]_p[fx,fy,fz,tx,ty,tz]+
groupfieldunits
1tcp_pose — x, y, z, rx, ry, rzm, rad
2tcp_speed — vx…wzm/s, rad/s
3joints — j0…j5rad
4wrench — fx, fy, fz, tx, ty, tzN, N·m

API Reference

The public surface. Per-module markdown lives in docs/api/.

UR5eRobot — the facade

UR5eRobot(config: RobotConfig = RobotConfig())
Construct the robot. No I/O happens until connect(). Usable as a context manager.
connect() → None  ·  disconnect() → None
connect() uploads the daemon then starts the state connection. disconnect() closes it (idempotent). Both are driven automatically by the with block.
move_l(pose, speed=None, accel=None, blocking=True, relative=False) → None
Linear (Cartesian) move of the TCP. pose is a world-frame [x, y, z, rx, ry, rz] in m/rad (a delta if relative=True). Converted to UR frame, workspace-checked, encoded, sent; if blocking, polls until within convergence_tol. raises WorkspaceViolation · SpeedViolation
move_j(joints, speed=None, accel=None, blocking=True) → None
Joint-space move. joints = [j0..j5] in radians (frame-independent). Joint-limit checked; if blocking, waits for the TCP pose to settle. raises JointLimitViolation · SpeedViolation
get_state() → RobotState
Parse the latest streamed frame into a RobotState (UR base frame). raises ValueError if no / malformed frame
stop() → None  ·  home() → None
stop() commands an immediate controlled stop (cmd 2, non-blocking). home() moves to config.home_pose (cmd 3).

Methods world_to_ur(pose) / ur_to_world(pose) convert between frames (default: negate x and y; z and rotations unchanged) and round-trip to identity.

RobotState

@dataclass
class RobotState:

safety

check_pose_in_workspace(pose, config)  ·  check_joints(joints, config)  ·  clamp_speed(speed, config)
Pure validators run before any command is sent. Exceptions: WorkspaceViolation, JointLimitViolation, SpeedViolation (all subclass SafetyViolation).

Safety

This commands a physical robot. Treat every move as live.

  • Keep the e-stop within reach. The physical emergency stop on the teach pendant is your real safety device — not robot.stop().
  • Clear the workspace of people and obstacles before connect(). The first command may move the arm immediately.
  • Start slow. Verify motions at low speed first. Keep max_speed conservative; it is a hard cap, not a suggestion.
  • Validate workspace_limits for your cell. Defaults come from a different setup. A pose outside bounds raises WorkspaceViolation and is never sent — set them correctly.
  • Force control is disabled by default. The daemon's cmd 4 branch is gated behind FORCE_MODE_ENABLED = False so a stray force command cannot drive the arm into a surface before the FT 300 is validated.
  • Dry-run first. Use the dry-run transport / examples to inspect the exact command strings before any of them reach the controller.
Verification scope. This library is tested only at the code level (parsing, command encoding, safety validation, control law via mocks). Motion correctness on real hardware has not been verified and must be confirmed by the operator on the actual UR5e + cell.

Force Control Robotiq FT 300 · forward-looking

Move along a direction until contact force reaches a target, then hold compliantly (impedance). Interfaces and the control law are implemented and mock-tested; on-robot tuning happens once the FT 300 is mounted.

Pending hardware validation. Step size, stiffness, threshold and max_travel are placeholders to tune on the real sensor. The daemon's force branch stays disabled until you set FORCE_MODE_ENABLED = True in motion_daemon.script after validation.

Sensor abstraction

A pluggable ForceSensor isolates the read path so the rest of the code never changes when you swap mock → real:

classuse
ForceSensorABC — read() → [fx,fy,fz,tx,ty,tz], zero()
RobotiqFT300(state_provider)real sensor; reads the wrench via a state provider (URCap-fed stream now, or a PC-side driver later)
MockForceSensor(sequence)scripted wrenches — test the control law with no hardware

approach-until-force, then hold

force demo (mock)
from ur5e_control.force.sensor import MockForceSensor
from ur5e_control.force.controller import ForceController

# wrenches climb toward contact; last one trips the 5 N target on +Z
sensor = MockForceSensor([[0,0,1,0,0,0], [0,0,3,0,0,0], [0,0,5.2,0,0,0]])
fc = ForceController(motion, sensor, config)

fc.approach_until_force(
    direction=[0, 0, 1],   # push along +Z
    target_n=5.0,           # until |F·d̂| ≥ 5 N
    stiffness=0.08,         # compliance once in contact
    max_travel=0.12,        # safety budget (m) before giving up
)

The law reads before each step (no overshoot): below-target reads issue one relative step along the unit direction; the contact read stops stepping and emits the cmd 4 hold. Contact is decided on the force projected onto the direction, so side forces never false-trigger. Exceeding max_travel raises RuntimeError and emits no hold.

Troubleshooting

symptomlikely cause & fix
Daemon won't start / no state arrivesThe robot must be in remote control mode. Confirm the daemon uploads cleanly (watch the PolyScope log) and that the controller can reach pc_host:state_port — the daemon connects back to the PC, so a PC firewall blocking 30002 is a common culprit.
ValueError from get_state()No complete state frame yet. Allow a moment after connect() for the stream to start, then retry.
WorkspaceViolation on a valid-looking poseDefault workspace_limits are for a different cell. Set them for your setup. Remember move_l input is world frame; the check runs after world_to_ur.
Blocking move raises TimeoutErrorPose never converged within the poll budget. Check the state stream is live and that convergence_tol isn't unreachably tight (mixing m and rad in one tolerance).
Controller rejects the uploaded scriptThe daemon must be raw URScript (no Python wrapper). script_sender sends the file verbatim; the controller auto-runs the single routine it receives.
Force command does nothingExpected until validated: FORCE_MODE_ENABLED = False in the daemon. Enable only after FT 300 bring-up.
Robot moves the wrong way in X/YFrame convention. world_to_ur negates x and y by default — adjust the transform in RobotConfig for your world frame.
